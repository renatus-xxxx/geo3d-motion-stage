# 実装とデータ形式

## BVHのbake

公式BVHは23関節、40 Hz・2,820姿勢です。`BvhBake.cs`が親子変換、OFFSET、位置、CHANNELに記載された順番の回転を評価し、End Siteも扱います。人体は12個の三角双錐で、1人60頂点・72三角形、3人180頂点・216面です。

基本bakeは20 Hz・1,410姿勢・70.5秒です。`CompactMotion.cs`が8 MiB用に全姿勢、2 MiB用に1姿勢おきの705姿勢・10 Hzを収録します。保存姿勢の座標と16 bit法線は元の値と完全一致します。小容量版は面の頂点番号を共通化し、geo3d用の面パケットを固定長RAMバッファで復元します。

座標はBVHの2倍スケールのint16で、全編の中心を引いています。X右、Y上、Z奥、行列・法線はQ2.14です。全編の範囲はX=-623..623、Y=-166..166、Z=-600..600、床Y=-174です。別データでは演算範囲を再確認してください。

## ROMの容量別構成

| 配置 | 8 MiB | 2 MiB |
|---|---:|---:|
| マッパー | ASCII16-X | ASCII16 |
| 保存姿勢／更新頻度 | 1,410／20 Hz | 705／10 Hz |
| 頂点／姿勢 | 1,080バイト | 1,080バイト |
| 面／法線 | 2,376バイト | 1,296バイト |
| 事前計算の境界 | 48バイト | 48バイト |
| 合計／姿勢 | 3,504バイト | 2,424バイト |
| 16 KiBバンク内の姿勢数 | 4 | 6 |
| データのバンク数 | 353 | 118 |
| 使用バンク | 0..354 | 0..119 |
| 未使用の丸ごとのバンク | 157 | 8 |

バンク0はABヘッダーと起動処理、1はRAMへコピーするCコード、2以降は姿勢です。未使用領域をFFhで埋めます。データのバンク領域は5,783,552／1,933,312バイトです。起動・コードを含む使用バンク領域は5,816,320／1,966,080バイトですが、バンク内のパディングを含み、全てが有効データではありません。

```c
stored = frame / SAMPLE_STRIDE;
bank = 2 + stored / POSES_PER_BANK;
pose = (const unsigned char *)(0x4000 +
                              (stored % POSES_PER_BANK) * FRAME_BYTES);
```

2 MiB版は6000hへバンク番号を書きます。8 MiB版はさらにアドレスの8..11 bitへ上位バンク番号を指定します。切り替えるのは第1窓だけで、コード・スタック・割り込みはRAM上です。ASCII16-XはROMオフセット16の`ASCII16X`で識別します。2 MiB版はこの識別子を含めず、ASCII16として明示的に読み込んでください。

## 表示範囲の事前計算とカメラ

各姿勢の末尾48バイトに、全員と各人物の4つのワールド座標AABBを保存します。1つは最小X/Y/Z・最大X/Y/Zのint16×6です。これは頂点を走査して最小・最大を求める処理だけを置き換えます。カメラ、投影、ズームを保存するものではありません。

描画時は毎回、次の処理を行います。

1. 現在と過去の姿勢を選び、境界を合成する。
2. `2*FLOOR_Y-Y`の映り込みと、従来の安全余白を含める。
3. 中心と現在のカメラ回転行列を計算する。
4. 境界の8つの角を、カメラ座標へ変換する。
5. 画面端・近クリップを満たす距離を求め、ズームを適用する。

したがって手動・自動のカメラ回転は引き続き自由です。ズーム100..200%は必要な最小距離から引く操作で、人物を収めます。人物選択・効果によって必要距離は変わります。カメラを固定する近道や新しい平滑化は導入していません。全姿勢の境界が元頂点の走査と一致することをデータ検証で確認し、実際の描画時の人物・残像・映り込みの投影も別途検証します。

## RAMと起動

0000..3FFFはBIOS、4000..7FFFはROMデータ窓、8400からCコード・定数・BSSです。BSSがE000を越えるビルドを拒否します。E000..E100はIM2、E1E1..E1E3はJP、E200付近は起動ヘルパー、F300から下向きにスタック、F380以降はBIOS作業領域です。

必要主RAMは64 KiBのままで、アプリはRAMマッパーを使用しません。2 MiB版だけ2,376バイトの面復元バッファを使用します。正確なコード・BSS終端は生成STAGEマップに記録します。起動時にページ2をページ3のRAMスロットへ合わせ、本体／外部V9968を検出し、CHGMODを使わずSCREEN 7 FILを直接設定します。[VDPの検出・同期](VDP.ja.md)を参照してください。BIOS世代002Dhが3でCHGCPUが存在する場合だけR800 DRAMを選び、それ以外はZ80です。

## FILとgeo3d

配布は全てSCREEN 7 FIL・512×424・16色・RGB5パレット・VRAM 256 KiBです。openMSX用はR20=11h／R21=7AhでY=512から0へ完成画面をコピーします。nativeはR20=31h／R21=3Ahで表示ページを切り替えます。容量やCPUとは独立した設定です。R9=84hで60 Hz・212行／フィールド・EOを明示します。

geo3dへ選択した9Dh／9Fhまたは8Dh／8Fhから行列、平行移動、頂点、面、光源を転送し、変換・面ソート・塗りつぶしを任せます。mainはgeo3dとVDPの完了を待ちます。映り込みは頂点Y、巻き方向、法線Yを反転します。残像は100／200 ms前の骨格線で、開始時に末尾の姿勢へ循環しません。床は5×5頂点・4×4マスと地平線の塗りです。アルファ合成・画像補間は使用しません。

## 共通デモ時計

VBlank割り込みで上限付きの再生時計、音楽フェード、PSG、入力エッジを更新します。割り込み内で描画・BIOS呼び出し・ROM切り替えは行いません。mainは時計を原子的に読み、論理姿勢を`ticks/3`で選びます。間引きは保存形式だけに作用し、再生時間を変えません。

`demo_update(t)`は現在時刻から効果・人物・カメラを直接決めます。トグルイベントの再現ではないので、遅い描画でも設定を取りこぼしません。ただし短い中間状態は見えない場合があります。表示操作で現在の場面を保持して手動へ移り、Dで新しいデモ、Mは音だけ、Escは現在のモードを初期化します。

最後の30 tickで白化・消音し、表示後は再描画せず1秒の白画面を保持します。白画面のまま状態・面キャッシュを初期化し、次の最初の画面を表示してからパレットと音楽時計を戻します。この準備時間だけCPUに応じたループ間の待ちが加わりますが、再生中の踊りと音楽はVBlank基準です。

自由走行時計と表示枚数はunsigned 16 bitで一周します。経過時間はunsigned差分を使い、再生時計は4,230、保持時計は60で止めます。遠い絶対時刻との等値比較は行いません。自由走行時計は60 Hz換算で約18分で一周します。50 Hzは未対応で、追加時は姿勢・演出・フェード・PSG全体の時間変換が必要です。

## 独自PSG音楽

`music.c`は32段階×15 tick、約8秒・120 BPMのループです。Aはアルペジオ、Bはベース、Cはノイズ／打楽器です。ミュート中も位相を保持して進め、解除時は現在の音を復元します。ポーズは姿勢と音楽位相の両方を止め、ループ再開は音楽を初期化します。公式MP3は使用しません。
