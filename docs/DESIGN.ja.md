# 実装とデータ形式

## BVHからの変換

参照BVHは23関節・2,820フレーム・0.025秒/フレームです。
`tools/BvhBake.cs` は関節の親子構造を読み、OFFSET、位置CHANNEL、
データに記載された順番の回転CHANNELからワールド座標を求めます。
End Siteも頭の先端として使います。回転順をXYZに固定していません。

毎2フレームから1姿勢を生成し、1,410姿勢・20Hz・70.5秒に変換します。
複雑な人体スキニングは行わず、頭、胸、腰、腕、脚を12個の三角双錐で表現します。
1パーツは5頂点・6三角形。幅は部位に応じて変え、姿勢ごとに外向き法線を生成します。

座標はBVH単位を2倍した符号付き16bit整数です。全編の境界中心を引き、
原点付近へ配置します。Xは右、Yは上、Zは奥。行列と法線はQ2.14です。
生成した全編の境界はX=-623..623、Y=-166..166、Z=-600..600、床Y=-174です。
大きな値や別のデータを使う場合は量子化・投影演算の範囲を再確認してください。

## ASCII16-X ROM

8MB = 512個の16KBバンクです。

| バンク | 内容 |
|---|---|
| 0 | ABヘッダーとROM INIT |
| 1 | RAMへコピーするCプログラム |
| 2..354 | モーションデータ：353バンク |
| 355..511 | FFhで埋めた未使用領域 |

1姿勢は3,456バイトです。

| 領域 | 形式 | サイズ |
|---|---|---:|
| 頂点 | 180個×X,Y,Zのint16、リトルエンディアン | 1,080バイト |
| 面 | 216個×4頂点番号、NX,NY,NZのint16、BASE色 | 2,376バイト |

各バンクには4姿勢を収録し、残りはFFhで埋めます。
最後のバンクには2姿勢を収録します。データ領域は5,783,552バイトです。
三角形は第4頂点を第3頂点と同じにするgeo3dの形式です。

```c
bank = 2 + frame / 4;
address = 0x4000 + (frame & 3) * 3456;
```

ASCII16-Xでは、バンク番号の上位ビットをレジスタ書き込みアドレスの8..11bitに指定します。
このROMでは第1窓だけを使います。

```c
*(volatile unsigned char *)(0x6000 | (bank & 0x0f00)) = (unsigned char)bank;
```

ROMファイルのオフセット16に8バイトの識別子`ASCII16X`を収録し、対応エミュレータでの自動判別も検証しました。
通常のASCII16として扱うと256番以降のバンクを正しく選べません。
コード、変数、スタック、割り込みはRAM上にあり、切り替える第1窓に実行コードを置きません。
姿勢はRAMへ全コピーせず、固定したROMバンクからgeo3dへ直接転送します。
割り込みはカートリッジのバンクを変更しません。

## RAMと起動

| アドレス | 用途 |
|---|---|
| 0000..3FFF | メインBIOSを保持 |
| 4000..7FFF | カートリッジの16KBデータ窓 |
| 8400..A06B | Cプログラム・定数・BSS：現在のビルド |
| E000..E100 | IM2の257バイトのベクターテーブル |
| E1E1..E1E3 | RAM割り込み処理へのJP |
| E200付近 | 起動時のRAMコピー用ヘルパー |
| F300以下 | 下向きに伸びるスタック |
| F380以降 | BIOS作業領域を保持 |

最低64KBのメインRAMを想定します。ゲーム用RAMのバンク切り替えは行いません。
起動時にページ3と同じRAMスロットをページ2へ選び、カートリッジのプログラムをRAMへコピーします。
BIOSの世代番号002Dhが3で、CHGCPUの入口が存在する場合だけR800 DRAMへ切り替えます。
BIOS呼び出しではCコンパイラのフレームポインタIXを保持します。

起動時はBIOSのCHGMODでVDPを初期化した後、video_init()がVDPレジスタを直接設定し、配布版のSCREEN 7 FIL・512×424・16色へ移行します。描画中のVBlank時計は専用のIM2割り込みで管理します。
メインの描画処理がVDPレジスタを所有し、割り込みはVDPのVBlank確認、時計更新、PSG再生、入力エッジ検出を行います。Cの割り込み処理を呼ぶ前後でAF/HL/BC/DE/IX/IYと裏レジスタを保存・復元します。
入力はPPIのキーマトリクスを直接読みます。

## 描画とカメラ

V9968は512×424、16色、RGB5パレット、通常ROMはR20=11h、R21=7Ah。native版はR20=31h、R21=3Ahです。
SCREEN7 FILを有効にします。VRAMのY=0と512を表示・描画領域として使います。
このエミュレータ環境ではVDPが98h..9Ch、geo3dが9Dh/9Fhです。

geo3dへカメラ行列、平行移動、頂点、面、ライトを送ります。
geo3dとVDPの処理完了を待ち、RUN busy中にVDPコマンドを発行しません。
入力はVBlankごとに検出して保持し、メイン処理ではDI/EIで保持キーの読み取りとクリアを排他します。

現在姿勢と表示する過去姿勢の境界を求め、反射がONなら床で反転したYの範囲も含めます。
境界中心を注視点として8隅をカメラ座標へ変換し、
X・Yの投影範囲とnear planeを満たす最小距離を計算します。
ズームはその距離の100..200%です。全頂点が収まる位置より近くへ寄れません。

床は水平面の消失線以下を塗り、5×5頂点・4×4区画の3Dチェッカー床を重ねます。床の範囲を維持し、区画の辺長は350から175へ半分にしました。
反射はYを`2*FLOOR_Y-Y`へ変換し、面の頂点順と法線Yを反転します。
残像は100ms前と200ms前の骨端点を暗い2色の線で描き、最後に現在の立体メッシュを描きます。
3人分の残像1姿勢は72頂点・36辺です。過去姿勢をもう一度塗りつぶす方式から軽量化しました。
アルファ合成・物理的な反射・時間方向の画像ブラーは行いません。

姿勢は20Hzの時計から選びます。描画の間に時間が進んだら次の必要な姿勢へ進めるので、
Z80でも再生がスローモーションにはなりません。補間とループ継ぎ目の平滑化は未実装です。

## PSG BGM

src/music.cは32ステップ×15 VBlank（約8秒、120 BPM）のオリジナルシーケンサです。Aチャンネルは明るいアルペジオ、Bはベース、Cはノイズと短いトーンの打楽器です。PSG周期はMSXの標準クロックを基準とし、レジスタ7の上位2bitを保持します。コードと音符表はRAM上にあり、ROMバンク変更中も割り込みから読めます。Mでミュート、Spaceで停止、Escで再開始します。

SCREEN7 FILの方式、表示コピーとnativeページ切り替え、白フェードと終了操作はVERIFICATION.mdに詳述しています。
